# P0 — AI 多平台风格自适应改写

> 版本：v0.2 P0。状态：设计定稿。
> 目标：同一篇「母稿」，发布到各平台时按平台调性自动改写，解决"一次写、全平台水土不服"的核心痛点。

---

## 1. 背景与问题

当前 OmniPost 全平台发同一份正文。但平台调性差异巨大：

| 平台 | 调性 |
|---|---|
| 知乎 | 深度论述、有理有据、段落长 |
| 微信公众号 | 标题党、排版分段、口语转述 |
| 小红书 | 口语化、种草口吻、emoji、话题标签 # |
| 微博 | 精简、140~2000 字、带话题 |
| X / Twitter | 精炼、280 字、可双语 |
| Bluesky | 300 字素、去中心化社区口吻 |
| 掘金 / CSDN | 技术干货、代码块、结论先行 |
| Telegram | 简洁、结构化 |

硬发同一份正文，各平台都"水土不服"，读者跳出率高。

---

## 2. 方案

**核心机制**：每个平台 adapter 声明自己的风格要求（`stylePrompt`），发布时若开启「AI 适配」，则用母稿 + 平台风格 prompt 逐平台改写，再分别发布。

```
母稿（title + body）
   │  开启 AI 适配
   ├─→ 知乎 stylePrompt → 知乎改写稿 → 发知乎
   ├─→ 小红书 stylePrompt → 小红书改写稿 → 发小红书
   ├─→ X stylePrompt → X 改写稿 → 发 X
   └─→ ...（每个平台独立改写）
```

**降级策略**（关键，保证不阻塞发布）：
- 某平台改写失败（API 报错 / 超时 / 无 key）→ **自动回退母稿原文**，照常发布，并在结果里标注"未适配"。
- 未配置 AI key 时，开关默认关闭且不可用。

---

## 3. 技术设计

### 3.1 平台风格库（`PlatformAdapter.stylePrompt`）

在 `core/types.ts` 的 `PlatformAdapter` 接口新增可选字段：

```ts
/** 平台风格描述（供 AI 多平台风格自适应改写使用） */
stylePrompt?: string;
```

各 adapter 在实现里补一段风格描述（中文，描述该平台调性、篇幅、语气、格式要求）。

### 3.2 改写客户端（`adapters/ai-client.ts` 新增）

```ts
export interface RewriteConfig { baseUrl: string; apiKey: string; model: string; }

export async function rewriteForPlatform(
  mother: { title: string; body: string },
  stylePrompt: string,
  config: RewriteConfig,
): Promise<{ title: string; body: string }>;
```

- 复用 `generateArticle` 的 OpenAI 兼容 `chat/completions` 客户端
- 系统提示词：`你是内容风格适配专家，把母稿按目标平台风格改写，保留核心信息与事实，调整语气/篇幅/格式，输出 JSON {"title","body"}`
- user 消息：母稿 + 目标平台风格
- `response_format: json_object`，解析复用 `parseArticleJson`

### 3.3 发布管线（`background/index.ts`）

`START_AUTO_PUBLISH` / `START_DRAFT_PIPELINE` 的 payload 增加 `aiRewrite?: boolean`。

在 `handleDraftPipeline` 的平台循环里，`createDraft` 之前：

```ts
let target = article;
if (aiRewrite && adapter.stylePrompt && aiConfig) {
  try {
    target = await rewriteForPlatform(article, adapter.stylePrompt, aiConfig);
    broadcastProgress({ stage: 'drafting', message: 'AI 适配平台风格...' });
  } catch {
    target = article; // 降级：改写失败用原文，不阻塞
  }
}
const draft = await adapter.createDraft({ ...target, mediaRefs });
```

- `aiConfig` 从 `store.getAiSettings()` 读取（复用 P0 之前的 AI 配置）
- 没有 stylePrompt 的平台（zip-download 等本地导出）跳过改写

### 3.4 popup 开关

发布区（底部操作条）新增复选框「✨ AI 适配各平台风格」：

- 仅当已配置 AI key 时可用
- 勾选后，发布 payload 带 `aiRewrite: true`
- 发布进度区显示「AI 适配中…」

---

## 4. 验收标准

1. 每个文字平台 adapter 有 `stylePrompt`（至少覆盖知乎/公众号/小红书/微博/X/掘金/CSDN 等核心平台）
2. 开启「AI 适配」后，发布到多个平台时逐平台改写（改写稿与母稿不同）
3. 改写失败 / 未配置 key 时，自动回退原文发布，不抛错、不阻塞
4. 未配置 AI key 时开关禁用
5. 关闭开关 = 原行为（全平台发同一母稿）

---

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| AI 改写耗时，多平台串行会慢 | 逐平台串行 + 进度提示；后续可并发池 |
| 改写偏离原意 / 编造 | 系统提示词强调"保留事实与核心信息"，仅调语气/篇幅/格式 |
| 改写花费 token | 用默认 v4-flash（经济）；关闭开关即零成本 |
