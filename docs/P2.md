# P2 — 多账号矩阵

> 版本：v0.2 P2。状态：设计定稿。
> 目标：同一平台配置多个账号（矩阵号），发布时一键切换，无需反复改凭证。

---

## 1. 背景与问题

矩阵号运营需要在同一平台持有多个账号（多个 WordPress 站、多个 Telegram 频道、多个 Mastodon 实例等）。当前每个平台只能配一套凭证，切换账号要手动改设置。

---

## 2. 方案

**平台级多账号 + 活跃账号切换**：

```
账号库：accounts[pid] = [{ id, name, config }]
活跃账号：activeAccountId[pid] = id
         ↓
store.getSettings() 动态合并「各平台活跃账号的 config」
         ↓
adapter 零改动（继续读 store.getSettings()，自动拿到活跃账号凭证）
```

**关键设计**：通过 `getSettings()` 的合并层实现"adapter 零改动"——adapter 仍读 `store.getSettings()`，但返回值已经是各平台活跃账号的配置。切换账号 = 改 `activeAccountId`，下次读取自动生效。

**范围**：仅对 **official 平台**（填凭证的：WordPress/Telegram/YouTube/X/Typecho/MetaWeblog/Bluesky/Mastodon/Reddit）支持多账号。session 平台（微博/小红书等 cookie 登录）一个浏览器一个登录态，多账号无意义，明确不支持。

---

## 3. 技术设计

### 3.1 账号库（`store/index.ts`）

```ts
interface AccountEntry { id: string; name: string; config: any; }

// store 新增：
listAccounts(pid: PlatformId): Promise<AccountEntry[]>
addAccount(pid: PlatformId, name: string, config: any): Promise<string>  // 返回新账号 id
removeAccount(pid: PlatformId, accountId: string): Promise<void>
switchAccount(pid: PlatformId, accountId: string | null): Promise<void> // null = 回退默认单账号
getActiveAccountId(pid: PlatformId): Promise<string | null>
```

### 3.2 合并层（关键）

`getSettings()` 改为：

```ts
async getSettings(): Promise<PlatformSettings> {
  const data = await chrome.storage.local.get(['settings', 'accounts', 'activeAccountId']);
  const merged = { ...(data.settings || {}) };
  const accounts = data.accounts || {};
  const active = data.activeAccountId || {};
  for (const [pid, accountId] of Object.entries(active)) {
    const acc = (accounts[pid] || []).find((a) => a.id === accountId);
    if (acc) merged[pid] = acc.config;
  }
  return merged;
}
```

- 无多账号的平台 → 走默认 `settings[pid]`（兼容旧数据）
- 有活跃账号的平台 → 用活跃账号 config 覆盖

### 3.3 popup UI

- 平台卡片（official 平台）右上角显示账号名 + 下拉切换（多账号时）
- 设置面板「多账号」区块：新增 / 切换 / 删除账号
- 顶部显示当前活跃账号名

---

## 4. 验收标准

1. official 平台可添加多个账号（每个账号独立凭证）
2. 切换账号后，`checkLogin` 用新账号凭证（发布目标随之切换）
3. adapter 代码零改动（通过 getSettings 合并层）
4. 旧单账号配置兼容（无多账号时行为不变）
5. 账号数据持久化

---

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 合并层影响旧行为 | 无活跃账号时回退默认 settings，行为不变 |
| session 平台多账号困惑 | 明确仅 official 平台支持，UI 上不显示切换入口 |
| 账号 config 结构各异 | config 存原始子对象（如 wordpress 的 {endpoint,username,appPassword}），不约定统一结构 |
